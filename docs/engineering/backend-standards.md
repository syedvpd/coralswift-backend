# Backend Standards

**Phase gate rule:** a phase is "complete" only after the gate (`ruff check . && ruff format --check . && mypy && pytest -q`,
live-server check, migration state) has been re-run after the last change and the results recorded. Phase 1 is currently
**implemented - verification pending**; Phase 2 does not begin until it passes. Never record a check as passed unless it was run.
Keep credentials out of docs, logs and commits; rotate any secret that has been pasted into chat or tickets.

## Code

- Python 3.12, full type hints, `mypy --strict` clean, `ruff` (lint + format, line length 100).
- Routers stay thin; rules live in services. No circular imports; modules talk through services.
- Reuse `app/common` and `app/core` helpers before writing new ones. No wrapper-only repositories.
- Sync endpoints and sync SQLAlchemy throughout. Do not mix in async DB access.
- Comments explain why, one line.

## API

- All routes under `/api/v1` (health endpoints are unversioned at root).
- Success: `{"success": true, "message", "data", "meta"}` via `ok()`. Errors: `{"success": false, "message", "error": {"code", "details"}}`.
- Statuses: 200/201 success, 400 bad request, 401/403 auth, 404, 409 conflict, 422 validation, 503 dependency down, 500 unexpected.
- Services raise `AppError` subclasses (`app/core/exceptions.py`); never return error JSON from routers by hand.
- Lists are paginated with `PageDep` / `page_meta`, page size capped at 100.
- Every response carries `X-Request-ID`.

## Errors and logging

- JSON logs to stdout. Log with `logging.getLogger(...)`; pass context via `extra=`.
- Never log passwords, tokens, secret keys, DB URLs, documents or unnecessary personal data. The formatter redacts common patterns, but do not rely on it.
- Do not catch exceptions to hide them. Unexpected errors reach the 500 handler, which logs the traceback and returns a generic message.

## Database

- Schema changes only via Alembic migrations. No `create_all`, no manual DDL.
- Never edit an applied migration; add a new one. Review autogenerated files before applying.
- Never drop/truncate/reset automatically. Destructive migrations need explicit sign-off and a two-step rollout.
- UUID primary keys and timezone-aware UTC timestamps (`UUIDPrimaryKeyMixin`, `TimestampMixin`, `app.common.utilities.utcnow`).
- Services own transactions: commit explicitly. Sessions are closed (and uncommitted work rolled back) per request.
- Money: integer minor units or `Numeric`, never float.

## Migration procedure

1. Change models; make sure the module's models are imported in `migrations/env.py`.
2. `alembic revision --autogenerate -m "..."`; read and edit the file.
3. Apply to a fresh disposable DB; then to a copy with data if the change is non-trivial.
4. `alembic upgrade head` in staging/production is an approved release step, run separately from app start.

## Testing

- `tests/unit` pure logic; `tests/integration` real PostgreSQL; `tests/api` through the HTTP layer with `TestClient`.
- Tests use `TEST_DATABASE_URL` (name must end `_test`) and the `db_session` fixture (rolled back after each test).
- New behaviour needs a test; a bug fix needs a regression test that failed first. Never skip or loosen tests to get green.
- Security-relevant changes need negative tests (wrong role, other tenant, bad input).
- Gate: `ruff check . && ruff format --check . && mypy && pytest -q`.

## Public submissions (Phase 1)

- Every public form schema extends `SubmitterIn` (`extra="forbid"`, explicit consent) and uses `app/common/validation.py` types.
- Create rows with `create_enquiry` inside one transaction; send email only via the outbox after commit.
- Confidential text never goes to logs, activity metadata, email or `enquiries.message`.
- Uploads: validate with `documents.files`, store via the `Storage` adapter, never return storage keys.

## Security

- Config only via env/`Settings`; secrets are `SecretStr`; production config is validated at startup.
- CORS restricted to configured origins; trusted hosts enforced; security headers on all responses; docs off in production.
- Authorization is enforced server-side in services, including object-level checks.
- Parameterised queries only. Validate input with Pydantic at the boundary.
- Request-size limits and TLS are enforced at the proxy/load balancer.
